# Independent review: local public-LR diagnostic

Date: 2026-11-12
Scope: read-only review of `experiments/local_public_lr`; no source edits, no formal training, and no publication. This review note is the only file written by the reviewer.

## Result

**Accepted for code and development-smoke readiness.** I found no unresolved blocking issue after the report-history fix. This does not validate a scientific result: the completed execution is a three-round synthetic smoke, and the formal input preflight explicitly reports that formal training was not started.

## Design and intervention check

- `design.py` registers exactly one strong/IID/seed1001 case and two branches. Both share the same 200-round `Spec`; the intended client weights are `[0.5,0.5,0.5,0.5,0.5,0.5]` for baseline and `[0.125,0.5,0.5,0.125,0.5,0.5]` for local LR.
- In `engine.py`, private updates, B teacher generation, relation exchange, graph, targets and public update schedule remain shared. Only the copied per-client config passed into `update()` changes `public_weight`; this gives clients 0/3 effective public LR 0.0125 and leaves clients 1/2/4/5 at 0.05. Both branches retain two public steps.
- Probe selection reuses the fixed 7901 stream and the exact public IDs frozen from the diagnostic input. Probes run as forward-only summaries; they do not modify heads or training RNG streams. T0/T1/T2 are before private SGD, after private SGD at the teacher snapshot, and after public SGD.

## Reference integrity and baseline gate

- The full input preflight records one case, both 200-round diagnostic references, shared initial-head digest and probe digest, and snapshots of the quantity and low-capacity-diagnostic environments/completion seals. The raw evidence is in `outputs/local_public_lr_review_20261112/preflight/audit.json`.
- The runner checks the official quantity source manifest, verified cached input and P3-style diagnostic references before either branch. Baseline is compared with the full historical quantity B run, round-by-round across all non-time fields and at every existing test checkpoint. A historical replay mismatch blocks local-LR execution.
- A baseline that fails the severe-collapse recovery criterion does **not** block the intervention: it is the reason to test local LR. The hard gate is historical replay integrity, not baseline recovery success.
- The smoke audit records two runs of three rounds, validates both records and confirms exact baseline non-time replay. It also verifies partial resume: the completed baseline SHA stayed fixed and only the missing local run was added. A second completed resume made no file changes.

## Report and recovery checks

- Recovery requires all six clients at rounds 160, 180 and 200 to have more than one occupied cluster and a largest-cluster fraction strictly below 0.99. Missing checkpoints or clients fail. There is no ACC-improvement requirement, and the report correctly limits a pass to releasing the severe-collapse flag.
- The initial report implementation shadowed its historical diagnostic reference dictionary with a row list. That would have broken report regeneration. The current code separates `history_runs` and `history_rows`; the completed report-regeneration audit says 15 files were regenerated byte-for-byte. Historical private-only and global-low-LR outcomes remain separately labeled.
- `client_rates.csv` distinguishes configured LR from applied LR and marks private-only historical updates inactive with effective LR zero.

## Validation evidence and limits

- Main-agent smoke audit: 2 synthetic runs × 3 rounds; all record validations passed; baseline replay passed; no formal training started.
- Main-agent test report: 4/4 tests passed. The noted synthetic KMeans warning and test CSV resource warning are test-only; they do not indicate formal runner issues.
- The formal preflight verifies data/reference availability and identities only. It is not a substitute for the user-authorized 200-round run.
- A future local-LR pass would be evidence for this single IID/seed1001 setting. It would not establish a unique cause, non-IID behavior, or general healthy clustering. Later teacher feedback remains coupled across clients.

## Final judgment

Code, source-closure, input preflight, historical baseline replay gate, report regeneration and smoke/resume evidence are consistent with the frozen protocol. **No unresolved blocker; ready for user-directed formal execution.**
