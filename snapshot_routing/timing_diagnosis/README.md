# 完整头部训练计时归因

固定 STL-10、M=4096、2048 条匹配边、200 轮。比较 E43 的 2021 与 2023 强非 IID，外加 2021 IID 作参照。B 全量计算，D 关系认证。上一轮的准备缓存、编码器快照和训练轨迹用于核对，逐轮比对教师关系、学生目标、头参数和应用层字节。

## 运行顺序

每个配置各跑两次 BBDD、DDBB、BDDB、DBBD，共 8 个四次运行块。三个配置共 24 块、96 次独立单线程计时。每个方法在四个运行位置各出现四次。按固定计划交错配置，每次运行从相同初始头开始并完整训练。B/B、D/D 的同方法差来自相邻运行。每块以两个 D 的均值减去两个 B 的均值比较方法。

采用 E43 训练入口，在原阶段边界采集墙钟与进程 CPU 时钟。报告头部初始化、私有更新、关系生成、交换、公共更新，以及各轮未进入这些阶段的时间。磁盘载入、轨迹日志校验、模型评估、打印和系统状态采样在计时区间外。逐进程记录持久数组和内存峰值、供电、系统休眠估算及可用的进程亲和性和优先级。进程 CPU 时钟在短阶段可能量化，报告基于累计的 200 轮时间。

## 判定

- 主诊断指标为「完整头部耗时减去关系生成耗时」。各配置、各时钟用相邻同方法绝对秒差的合并 90 分位数作为比较尺度，采用线性插值。完整结果每个配置有 6 个 B/B 和 6 个 D/D 差值。
- 某阶段的 D 额外耗时中位数超过同方法 90 分位数，并且 B 先跑和 D 先跑各至少三块出现 D 较慢，标记为持续额外耗时。两种时钟各自判定。逐阶段结果用于定位有差异的环节。
- 完整头部另给配对平均省时、秒差与胜出块数，展示是否达到 3% 的实用门槛。只有八个有效块齐全才作正式判定。
- 按整个块检查电源和休眠，沿用 E43 的插电口径。检测到至少一秒休眠时，最多按原顺序补测整个块一次，原始尝试继续保留。程序中断后续跑会重测未封存的整块。

## 启动

在原实验工作区根目录插电运行。默认使用本地 E43 和 E42 结果作为输入。

```powershell
D:\anaconda\python.exe -B -m snapshot_routing.timing_diagnosis.run --preset full
```

完成后查看 `outputs/snapshot_routing_timing_diagnosis_full/report.md`。 `stage_diagnosis.csv` 含阶段秒差及波动判定，`same_method.csv` 含原始相邻差，`block_metrics.csv` 含每块墙钟和 CPU 的配对差。

中断续跑加 `--resume`。E43、E42 输入可分别通过 `--source`、`--confirmation` 指定，输出可用 `--output` 指定。 `--preset smoke` 读取 E43 已有合成短测，两个划分各做一个四次运行块。
