# D 相对 E 的关系认证增量

复用 E42 的十八条 STL-10 教师轨迹。固定三个公共规模 512、4096、16384，三个种子 2021、2022、2023，两种划分。首轮初始化及随后的 199 次教师快照依次送入 E 和 D 各自的缓存。每轮硬关系与封存的 B 逐边核对，各端重算数与缓存字节再和 E42 独立计时原始记录核对。

## 三种测量

1. **同候选集合上的判边增量。** 在任何回退前观察候选簇集合。两端候选不相交、且至少一端仍有多个候选时，D 可以断言异簇，而只认证端点标签的 E 仍缺标签。在 E 与 D 各自的缓存状态上各做一次同候选比较。同步记录若使用这份候选集合，点认证和关系认证分别需要重算多少去重端点。首轮初始化没有证书，计算认证率时从第二轮开始。
2. **实际省下的去重端点。** 两种缓存独立持续演化，按真实回退记录 E 与 D 实际完整打分的端点数，保留首轮。每格也给出 D 相对 B 的端点降幅。不同缓存状态的实际端点差与同候选计数各自有独立字段。
3. **净耗时与缓存。** 对同一格联结 E42 封存的 B/E/D 秒数，利用原电源和休眠判据取有效配对，保留含缓存初始化的净时间、绝对秒差与胜出次数。持久认证数组字节按六端合计。回放探针只做计数。

三档的中位数、最小值和最大值都由各配置汇总。图中的圆点表示各个种子与划分配置，菱形表示同规模中位数。图中同时展示 D 相对 E 的增量和 D 相对全量 B 的规模边界。

## 运行

从工作区根目录启动。正式版默认读取已保留的 `outputs/snapshot_routing_confirmation_full`，短测 `--preset smoke` 读取当地保留的 E42 合成输入。可通过 `--source` 指定另一份已完成的 E42 输出。

```powershell
D:\anaconda\python.exe -B -m snapshot_routing.mechanism.run --preset full
```

默认写入 `outputs/snapshot_routing_mechanism_full`，中断后加 `--resume`。使用 `--output` 可另存一轮。

`report.md` 先列三档结果，`client_round.csv` 保留每轮各端计数，`cell_summary.csv` 和 `size_summary.csv` 给出配置和规模汇总。四联图输出为 `mechanism.pdf` 与 `mechanism.png`。
