# Fashion-MNIST 跨数据确认

用当前偏置净变化 D 验证第二数据集上的关系生成和完整头部耗时，比较全量 B、共用偏置净变化界的逐样本 E 和当前 D。

## 冻结配置

- M4096，2,048 条固定匹配边，K=10。IID 与容量约束 Dirichlet α=0.1 各用 seed 3101、3102、3103。每个种子两种划分共用公共样本与图。每种划分六端、每端 200 个私有样本，编码器宽度为 128、128、128、256、256、256。
- 复用 Fashion-MNIST 的官方 IDX 数据、原容量约束划分、私有去噪自编码器和 KMeans 准备流程。自编码器训练五轮，随后冻结特征。训练真值标签仅用于构造和核验划分，测试用固定的前 1,000 张测试图像。
- 复用 STL-10 对照中的线性头更新引擎。由各端 KMeans 中心初始化，私有每轮完整一遍，使用全客户端伪标签频数校正与强度 0.5 的间隔保护。每客户端每轮固定两批、每批 64 条公共学生边。采用相同的公共权重、学习率及应用层编码。
- 每格审计三条轨迹，并跑三个配对计时块。每个方法恰好占据每个运行位置一次，共 18 次审计、54 次独立单线程计时，均为 200 轮。只用固定的一个公共规模，跨数据结论对应各自冻结的表示准备和数据划分。

## 核查和判定

逐轮对每个方法的关系做全量打分复核，并比对解码关系、聚合计数、学生实际批次和目标、教师快照、头参数及字节。三种方法的原生头 ACC、NMI、ARI 与簇占用在每十轮检查点应完全一致。计时进程按审计记录核对逐轮摘要与教师端点数。

完整头部耗时为头初始化加全部轮次，包含私有更新、关系生成、交换和公共更新。共同准备、特征缓存读取、审计、评估及写盘单列或排除。报告 B 的生成耗时占完整头部的比例，并给出逐阶段耗时、打分端点、对应 MACs、缓存和应用层字节。

完整头部计时沿用 3% 实用门槛，每格要求三个合格配对中至少赢两对。每个划分的三个种子齐全且至少两个达标才通过该对照，分别判定 D/B 和 D/E。关系生成收益逐格报告。正式计时遵循已有插电与休眠规则，检测到至少一秒休眠时整体补测该块一次。原始尝试保留。

## 运行

在工作区根目录执行：

```powershell
D:\anaconda\python.exe -B -m snapshot_routing.fashion_confirmation.run --preset full
```

默认使用 `experiments/real_iid/data` 的四份官方 IDX gzip 文件，替换路径用 `--data-dir`。默认输出到 `outputs/snapshot_routing_fashion_confirmation_full`。在原命令加 `--resume` 可继续，保留已封存的区块。需重测时通过 `--output` 指定新目录。用 `--preset smoke` 可在同一数据集上完成两个划分的小规模三轮流程检查。

主要产物为 `report.md`、`comparisons.csv`、`paired_blocks.csv`、`runs.csv`、`quality.csv` 和 `completed.json`。逐客户端打分端点和相应 MACs 在 `client_widths.csv`。
