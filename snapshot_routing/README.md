# 精确关系生成的选路边界

以 E40 的 STL-10 冻结特征训练为参考。公共样本量取 512、4096、16384，对应匹配图 256、2048、8192 条边。每档沿用四个既有场景、两种头宽、六客户端、K=10、200 轮和固定的公共学生预算。不同规模各自使用其已审计的训练轨迹。实验包放在仓库根目录，以便已有 E40 续跑仍可使用原有的 experiments 源码清单。

## 路径与数据隔离

| 路径 | 每客户端的规则 |
|---|---|
| B | 每轮全量生成。 |
| E | 逐样本认证，刷新不确定标签。 |
| D | 关系认证，刷新有待判定的关系端点。 |
| S | 以公共规模和头宽查表，采用训练种子上的预计最快路径。缺少记录或内存不足时用 B。 |
| C | 从 S 的路径出发。在预计收益够付成本、余下轮数足够、内存和电源满足条件时，前 8 轮最多并行维护一个试跑候选缓存。通过配对时间余量才切换一次，随后仅继续选中路径。这里的两个候选在程序中串行运行。 |

先用原 E40 输入重新执行 B 训练，捕获真实教师参数和固定特征。逐轮比对原审计的教师、关系、聚合计数、学生顺序、目标、损失、头参数及通信。全量前向再次核对参考关系。五条路径各三次单线程独立进程重放，各自保有连续合法的缓存。每条路径及试跑候选逐轮和参考关系精确核对，核对时间在计时区间外。

S 和 C 的表按整种子留出。同一 seed 的两种划分一起留出。只读取其余种子电源检查完整的固定 B/E/D 配对数据，用同一客户端的 B 时间归一化，先在种子内、再在种子间取中位数排序。用其余种子观察到的最有利成本差估算试跑上限。C 的切换判断只用自己的启动前缀，扣掉 5% 或两倍配对差的中位绝对偏差中较大者，预计剩余节省还需覆盖实际试跑成本。C 的缓存预算每端 8 MiB，限制持久认证数组。进程峰值另外记录，含固定特征等输入。阈值是本轮实现选择，随运行清单冻结。

## 如何判读

- 每格报告五条路径的净关系生成耗时，包含决策、首轮缓存、试跑和正式生成。B/E/D 对照复用同一个生成器实现。磁盘读取、参考轨迹生成和逐边核对在计时以外。
- 边界表重点看 D 对 B/E、S 对 B、C 对 S。在同一配置的有效配对中，平均至少快 3% 且至少赢两块，记为本格有实用收益。希望 S 在小图避开慢路，在中图保留收益。C 的增量收益单独看，报告最差配置可由逐格 CSV 直接排序获取。
- 参照时间为每个客户端事后在 B/E/D 中为整条轨迹选定一条路径的耗时之和。没有逐轮拼接最低时间。报告相对参照多花的时间，并保留所有原始配对、校准支出、内存和电源记录。
- 正式运行用已知插电的电源采样、可用休眠记录且累计估计休眠少于 1 秒的配对块作主要统计，另给全计结果。只有一块时给描述性结果。阶段固定为先测 B/E/D、后测 S/C，存在批次间机器负载偏差，配对结果仍属于边界筛查。该阶段验证范围是 E40 已有配置的留出重放。

## 启动

在项目根目录打开 PowerShell，插电并保持电源模式一致。正式运行 12 次轨迹捕获及 180 次独立重放，预留约 1.1 GiB 输出空间。

```powershell
python -B -m snapshot_routing.run --preset full
```

中断后加 `--resume`。默认输入用已完成的 E40 本地归档，默认输出 `outputs/snapshot_routing_full`。报表为 `report.md`，逐格对照为 `boundaries.csv`，原始运行摘要为 `runs.csv`。已有输出若需保留并重新计时，可用 `--output` 指定另一目录，保持相同输入。默认 `--preset smoke` 使用本地 E40 合成输入，特意启动双路径试跑以覆盖审计流程。
