# 三档精确关系生成选路的新种子确认

固定候选为 M=512 用 B，M=4096 用 D，M=16384 用 B。B 全量生成，E 逐样本认证，D 关系认证。三个档位均来自 [E41 开发结果](https://github.com/cagfriend/federated-relation-certification/blob/6af3128/docs/evidence/EXACT_ROUTING_BOUNDARY_20261120.md)。

## 正式设计

| 因子 | 固定配置 |
|---|---|
| 种子和数据划分 | STL-10，2021、2022、2023，各做 IID 和 Dirichlet α=0.1，共六组。三个种子均未用于 E41 选路开发。 |
| 头部协议 | 六客户端，宽度 128×3 和 256×3，私有容量 100/200/300 各两个客户端，K=10，中心初始化、全客户端私有频数校正、全程 0.5 保护、两步公共 BCE。 |
| 公共库与边 | 每个种子按 E40 规则生成嵌套公共库，M=512/4096/16384，对应 256/2048/8192 条匹配边。快照筛选使用 512 个样本，选定编码器在同种子和划分的三档共享。 |
| 轨迹与计时 | 每格完整运行 B 教师训练 200 轮，逐轮验证全量硬关系、聚合计数和学生目标。B/E/D 使用相同特征和冻结的教师头序列，三组连续三元组各自轮换方法顺序。方法在独立进程、单线程中串行计时。 |
| 实验规模 | 18 条教师训练轨迹，54 个配对块，最多 162 次重放。初始化受阻仍保留在分母中并记录客户端。 |

主指标包括路径初始化、缓存建立和 200 轮关系生成净耗时。逐边验证、轨迹载入及教师训练在计时区间外。记录每种方法的持久认证缓存、进程峰值、重算端点、逐块配对胜数。三档固定规则直接使用对应的 B 或 D 测量记录。计时覆盖关系生成阶段。

每十轮评估一次原生聚类头，保存 ACC/NMI/ARI、簇占用和最大簇占比。开始训练后任一检查点的单簇或最大簇占比达到 99% 记为严重退化事件。每格质量来自同一条 B 教师训练，质量事件与计时结果同时报告。

## 事前判定

- **4096 档**要求 D 对 B、对 E 的配对均值各至少省时 3%，并各赢至少两块。
- **512 和 16384 档**检查 E 和 D 对 B 是否达到同一门槛。出现达标挑战者时，同时报告该格固定规则相对事后最快路径多花的秒数及比例。
- 逐格判定要求三组技术重复都具备插电采样、无电池或未知采样、可用休眠记录且估计休眠少于 1 秒。全部原始块保留并附全计统计。质量事件单列。以种子和划分识别配置，三个技术重复用于计时稳定性。

## 运行

在工作区根目录执行。默认读取工作区已有的 STL-10 二进制，输出到 `outputs/snapshot_routing_confirmation_full`，为公共库、教师轨迹及日志预留约 2.5 GiB。需要指定其他数据位置时用 `--data-dir`，需要另存一轮时用 `--output`。

```powershell
D:\anaconda\python.exe -B -m snapshot_routing.confirmation.run --preset full
```

中断后在原命令加 `--resume`。已有完整轨迹及配对块通过校验后复用，未完成的配对块按原顺序重跑 B/E/D 三次测量。合成模式用 `--preset smoke`，跑一个种子的两种划分及三档小图，每档一组配对。

`report.md` 汇总各档判定。 `cells.csv` 给出逐格选路代价及质量护栏，`comparisons.csv` 给出 B/E/D 的配对结果，`runs.csv` 和 `quality.csv` 保留运行和检查点明细。
