# 学生所需边的精确按需对照

固定 STL-10、种子 2021、IID 与 Dirichlet α=0.1。M=4096，固定匹配图 2048 条边，六客户端，原训练协议各跑 200 轮。每个学生继续按原随机流取两批各 64 条边。最多有 768 条不同需求边，占全图至多 37.5%，逐轮测量实际并集大小。

## 四条路径

B 全量打分、E 逐样本认证、D 关系认证。三条路径复用 E43 的完整关系表与全量或差分传输协议。Demand 采用固定聚合者和可靠内存消息，按以下顺序执行。

1. 六个学生先按原随机流确定本轮边顺序，把原本发生在公共更新中的采样移到教师打分前。非聚合者用定宽位打包发送自己的边 ID，聚合者计算并集，用全图位图通知教师。
2. 六个教师分别对所需端点去重、打分、生成同簇标志。聚合者接收位打包教师票，按边统计来自全部教师的票数。
3. 聚合者按每个学生请求的原顺序发送压缩计数。确认与提交消息实际序列化并记账。每个学生按原顺序、批次及权重更新自己的头。并集外的边无提交状态。

公共图注册和票数/关系压缩复用既有消息编码。计入真实生成的请求、位图、票、计数和确认字节。按需对照的通信和计算代价对应这里的显式请求协议。原始图像分发、真实网络延迟与故障恢复属于其他测量口径。

## 核验与计时

- 先做 8 条不计时审计轨迹。Demand 的每轮并集、教师票和聚合计数都与全图参照核对，逐轮验证样本对顺序、学生收到的目标、私有及公共损失、教师和更新后头参数。评估检查点的原生头质量逐项对齐。在同一格内，B/E/D 额外核对全图关系、计数和应用层字节一致。
- 审计全部通过后做 **24 次独立进程计时**。每格三次四方法配对块，组内串行轮换顺序，两个划分使用镜像顺序，交错运行。每个进程单线程、复用已校验的准备输入，重新初始化头并执行完整训练。
- 主指标为含初始化的完整头部耗时。教师打分与关系生成单列，另报告需求协调加生成加交换。Demand 的协调阶段包含提前的学生采样，完整头部时间计入各路径实际发生的学生采样。记录平均省时、绝对秒差、配对胜出数、通信上下行和进程峰值。每格平均省时至少 3% 且至少赢两个有效配对块标记为达到门槛，三块有效数据齐全才作正式判定。
- 睡眠和中断按整块处理。明确记录到至少一秒休眠时按原顺序整块补测一次。报告保留原尝试和有效配对范围。

## 运行

插电后在工作区根目录运行，默认使用 E42 本地轨迹和数据缓存。

```powershell
D:\anaconda\python.exe -B -m snapshot_routing.on_demand.run --preset full
```

默认输出 `outputs/snapshot_routing_on_demand_full`。中断后加 `--resume`，未封存的完整配对块重测。使用 `--confirmation` 指定上一轮确认目录，`--output` 指定输出位置。`--preset smoke` 用两个合成划分，各做一个小图配对块。

先看 `report.md`。逐格及逐块时间、字节和峰值可查 `comparisons.csv`、`paired_blocks.csv` 和 `runs.csv`。逐轮实际需求边覆盖率可查 `demand_scope.csv`。
