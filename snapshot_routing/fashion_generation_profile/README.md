# E55 教师关系生成耗时归因

要解释的现象是 Fashion-MNIST M4096 上当前 D 减少了教师打分 MACs，但多数配置的生成阶段更慢，六组完整头部均慢于 B。[E55 已发布结果](../../docs/evidence/MATCHED_BASELINES_AND_FASHION_MNIST_20261123.md)

## 冻结设计

- 沿用 E55 的 3101、3102、3103 和 IID / Dirichlet α=0.1，合计六格。每格固定 M4096、K10、六客户端、200 轮、宽度 128×3 和 256×3、每端 200 张私有样本、同一匹配图、中心初始化、两步公共更新以及各端既有权重。使用已有 E55 准备缓存时，校验全部缓存文件与分区身份。也可用相同配置从官方数据重新准备。
- 用全量 B 跑一次独立审计。逐轮检查全量打分硬关系、聚合计数及学生消费目标。之后每条 B/D 路径均与该审计比对初始化、教师头、逐端关系、聚合目标、学生顺序与目标、损失、更新后头参数和通信摘要。通过这些检查后，两种方法的教师轨迹等价；各自仍连续执行完整训练，不从上一轮或另一方法借用认证缓存。
- 每格做四个无插桩 B/D 配对，块内交替顺序，每方法先跑两次。该部分合计 48 次独立进程。计时与 E55 一致，包括初始化和全部头部轮次。模型准备、缓存载入、逐轮结果摘要、审计和报表排除在墙钟窗口之外。单线程 CPU，插电且可读取休眠时间；不合格的整块补测一次。技术重复用于估计运行波动，种子用于跨配置判断。
- 每格另做一对 B/D 插桩运行，合计 12 次。每客户端逐轮记录首轮初始化、权重与偏置更新、候选界、位集合、边判定、端点收集、特征行拷贝、矩阵乘法与偏置加法、标签选择和检查、缓存写回、确定最终关系。记录端点数、候选项数、刷新前已认证边数、客户端宽度、外层生成墙钟与未归入阶段的残差。首轮全量打分与缓存建立合并记账。检查插桩和无插桩结果的轨迹及重算端点一致。

## 归因与后续验收

每格先看无插桩的生成和完整头部 B−D 差、四块配对差和端点 / MACs，再看插桩的账本。第 2 轮起的打分省时为 B 的打分耗时减 D 的打分耗时。额外耗时由 D−B 的首轮、其余阶段和计时残差组成。比较两者可以判断打分节省是否抵得过认证开销。逐端点和轮次诊断保留在 CSV，可按宽度及 D 的重算比例查看变化。

只有在无插桩生成差与插桩生成差方向一致，且最大阶段增量大于插桩残差的绝对方法差时，才把该格作为优化线索。若最慢的两个强非 IID 配置（3101、3103）指向同一阶段，优先只优化该阶段。方向反转、阶段不一致或差额接近计时残差时，先重复插桩配对。插桩测量用于归因，完整头部性能以无插桩计时为准。

选定优化之后，增加旧 D、改进 D、B 三方配对，运行真实数据完整 200 轮。验收要求保持上述逐轮等价，记录每个种子的生成和完整头部耗时及配对胜场，沿用 E55 的 3% 实用门槛评价改进 D 相对 B 的完整头部收益。此包提供归因和基线计时，优化内容由归因结果决定。

## 本地运行

在仓库根目录执行。短测使用官方 Fashion-MNIST 的四份 IDX gzip 文件，只跑 seed 3101 的两个划分和三轮。

```powershell
python -B -m snapshot_routing.fashion_generation_profile.run --preset smoke --data-dir <Fashion-MNIST数据目录>
python -B -m snapshot_routing.fashion_generation_profile.run --preset full --data-dir <Fashion-MNIST数据目录>
python -B -m snapshot_routing.fashion_generation_profile.run --preset full --cache-dir <E55输出目录下的cache>
```

默认输出 `outputs/fashion_generation_profile_<preset>`。用 `--output` 指定新目录。中断后用原命令追加 `--resume`，已封存配对保留，未封存配对整体重跑。

`report.md` 给出逐格方向与阶段摘要，`paired_blocks.csv` 保存每次无插桩配对，`diagnostics.csv` 保存逐格阶段差与诊断判据，`phases.csv` 保存插桩逐轮逐客户端记录。`runs/` 与 `blocks/` 中的记录有 SHA-256 回执。
