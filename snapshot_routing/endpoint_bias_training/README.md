# 偏置净变化 D 的完整头部收益确认

## 问题与配置

E49 在存档教师快照上测了新版 D 与旧版 D 的关系生成。这里验证当前默认 D 在完整头部训练中，相对全量关系计算 B 能否节省实际时间。两种方法使用同一个训练引擎，唯一开关是教师关系生成方式。

| 项目 | 冻结设置 |
| --- | --- |
| 数据 | STL-10，IID 与 Dirichlet α=0.1 |
| 种子 | 2022、2023，共四格 |
| 公共库与图 | M4096，2048 条固定匹配边 |
| 训练 | 六客户端、冻结编码器、异宽线性头、200 轮。复用 E42/E43 的中心初始化、全客户端频数校正、私有保护及每轮两步公共更新 |
| 配对 | 每格四对，BD、DB 各两对。按重复编号轮转配置顺序。共 32 次独立进程，串行单线程 |
| 审计 | 每格先独立跑一条当前 D，复用已封存的 E43 B 审计作锚 |

复用 E42 准备缓存、样本库、教师轨迹和 E43 所选模型快照。每次启动核对初始头、私有伪标签、图和公共样本标识。审计逐边核对硬关系，复算学生批次顺序并核对聚合目标。计时进程逐轮核对与 B 锚一致的关系、聚合计数、学生实际消费的目标与边顺序、教师快照、更新后头摘要及应用层通信。审计失败时停止，错误引用到配置和轮次。每十轮在审计中记录逐客户端 ACC、NMI、ARI、簇大小、最大簇占比及空簇。

## 计时与判定

- 主指标为完整头部墙钟，计入头部初始化、固定特征计算与全部 200 轮训练。另报私有更新、关系生成、交换及提交、公共更新和其他开销。关系生成计入首轮缓存构建。数据载入、共同编码器准备、轨迹校验、评估和输出在计时区间外。另记录进程 CPU 时间用于定位波动、前向端点数、应用层上下行字节、持久缓存与工作集峰值。
- 保留 E43 的 3% 实用门槛。每格在四个合格配对齐全时，用 B 和 D 的配对平均耗时计算省时比例。完整头部至少省 3% 且 D 至少赢三对才达标。每种划分的两个种子都达标才支持该划分上的结论。技术重复先在种子内汇总。
- 强非 IID seed 2023 单列完整头部、生成及其余阶段的配对差值和先后顺序。E49 该配置的 +6.89% 开销来自新版 D 对旧版 D，本实验回答新版 D 在同一配置相对 B 的实时生成和完整头部表现。
- 正式主表沿用 E43 的插电和休眠检查。检测到至少 1 秒休眠时按原顺序补测完整配对一次。每次尝试都保留，原始配对另列，缺少合格配对则显示配对不足。中断续跑时保留已封存的配对，未封存配对从第一种方法重跑。更换代码、源数据或环境后使用新的结果目录。

## 运行

在实验工作区根目录执行，沿用当前本地 E42/E43 结果。正式实验开始前接通电源。

```powershell
D:\anaconda\python.exe -B -m snapshot_routing.endpoint_bias_training.run --preset full
```

默认输出为 `outputs/snapshot_routing_endpoint_bias_training_full`。中断续跑加 `--resume`。源目录移动时用 `--source` 指定 E43 结果，用 `--confirmation` 指定匹配的 E42 结果。合成短测用 `--preset smoke`，复用已有 M64 合成输入。真实数据短测用 `--preset real-smoke`，每格一对、每条轨迹 10 轮。两种短测均无正式达标判定。

完成后查看 `report.md`、`comparisons.csv`、`paired_blocks.csv`、`runs.csv` 和 `quality.csv`。逐轮计时及审计证据保存在 `timing/` 和 `audit/`，完成标记是 `completed.json`。
