# 共享日程 Demand 的通信与完整头部耗时

E54 的 STL-10 M4096 配置中，显式 Demand 每 200 轮用 225,000 字节上传学生请求，另用 305,000 字节下发并集位图。共享日程在注册时传输固定采样设置，各端每轮独立重建请求并集。实验检验注册后的实际净通信节省，以及重建成本对完整头部耗时的影响。[E54 逐次账本](../../docs/evidence/e54_paired_boundaries/runs.csv)

## 冻结设计

- 使用 E54 的 12 个 M4096 配置。六个种子 2021–2026 各覆盖 IID 与 Dirichlet α=0.1。六客户端、固定匹配图、冻结编码器、相同教师和学生时序，每格 200 轮，学生每轮两批公共边。2021–2023 复用已完成的 E42 轨迹，2024–2026 按 E54 原设置重建参考。种子已经用于 E54，本实验用它们做匹配的协议对照。
- 每格比较 **全图 D、显式 Demand、共享日程 Demand**。全量 B 单独审计，提供全图关系和学生轨迹参考。每格六个主计时块，三种方法的六种排列顺序各用一次，共 216 次有效计时和 48 次独立审计。不合格的整块补测一次，记录所有尝试。完整头部沿用 E54 窗口，含初始化和全部训练轮。
- 共享版保留原图注册，每个远端另收到一条序列化的日程注册及回执。注册消息绑定图标识、公有样本顺序摘要、种子、固定成员编号、采样器和 NumPy 版本、公共步数和批大小。各端保留自己的学生请求，独立重建其余五端的请求及排序后的并集。完整协调计时包含全部六端的计算，含学生本地采样。按需投票、计数返回和回执继续实际序列化。
- 逐轮核对每端重建的有序请求和并集、并集上的教师票与 B 关系、聚合计数、学生目标、顺序、损失、头参数、评估和重算工作量。两种 Demand 的投票、返回目标和回执字节须相同。字节对账必须满足显式总量减去请求和位图，再加日程注册及回执，等于共享版的实际总量。上下行各自对账。

## 判据

按配置报告共享版对显式版和全图 D 的应用层上行、下行、总字节和消息数。另列协调、教师生成、交换及完整头部墙钟，独立审计记录每端补算其他成员请求和形成并集的耗时。逐进程及逐块记录均保留。

共享版相对显式版的完整头部容许平均增时 3%，六个块中至少四个须在相同边界内。相对 D 单独判断是否平均省时至少 3% 且至少赢四个块。与各自对照配对的净通信变化独立报告。若共享版省下字节但耗时越过门槛，保留计算与通信的权衡结果。配对块为同一种子的技术重复。

测试使用固定成员、同版本采样器、单线程 CPU 和可靠的串行内存消息。实测字节为应用层序列化字节。成员变更、异常恢复和不同采样实现之间的互操作另需验证。

## 运行

正式运行需要匹配的 E42 完整输出以及 STL-10 五份官方二进制文件。需要插电和可观测的休眠时钟。

```powershell
python -B -m snapshot_routing.shared_schedule_demand.run --preset full --confirmation $e42 --data-dir $stl10
```

独立流程短测使用合成数据、种子 2024 的两个划分和单个配对块。

```powershell
python -B -m snapshot_routing.shared_schedule_demand.run --preset smoke
```

默认写入 `outputs/snapshot_routing_shared_schedule_demand_<preset>`。可用 `--output` 指定空目录，或用原命令加 `--resume` 复用有回执的原记录。主报告为 `report.md`。原始分项见 `bytes.csv`、`paired_blocks.csv`、`runs.csv`、`reconstruction.csv` 和各运行回执。
