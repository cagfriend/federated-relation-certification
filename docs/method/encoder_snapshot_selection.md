# 训练前的编码器快照筛选

快照筛选用于冻结编码器前的本地初始化。这里的训练先用私有无标签图像更新自编码器，再用固定特征拟合 KMeans。簇中心用于初始化线性头，固定伪标签用于私有训练。一旦编码器把大部分样本投到同一个簇，后续的防共簇训练也可能保留这一分布。

## 何时触发

1. 每个客户端用最终快照拟合私有 KMeans，检查实际占用的伪簇数。少于设定的 (K) 时回查较早快照。现有私有频数校正要求每簇有样本。
2. 用同一批公共无标签样本检查预测集中程度。当前 STL-10、(K=10) 的多客户端诊断在私有或公共最大簇占比超过 50% 时回查早期快照。公共预测仍分散时，单独的私有偏斜也可能反映真实非 IID 分布，部署时宜将其视为风险提示。50% 是定向诊断使用的门槛，普适阈值仍待确认。
3. 对触发的客户端，先选私有 (K) 簇齐全且两侧最大簇均在门槛内的候选，再按公共同簇概率升序选择，并列时保留较晚快照。若找不到满足集中度门槛的候选，仍可从 (K) 簇齐全的候选中取最低分，但应记录集中风险。所有候选都缺簇时记录启动失败。终点通过检查时保留终点。

若公共集有 (M) 个样本，第 (k) 簇人数为 (n_k)，随机抽取两个不同样本被判为同簇的概率是

\[
\frac{\sum_k n_k(n_k-1)}{M(M-1)}.
\]

分数只用公共簇人数。候选的编码、聚类和决策都在客户端本地完成，留出真实标签仅用于事后评估。

## 证据与边界

- 五个新种子的十个配置中，固定 client1 第 4 步有 4/10 完成 200 轮，比较第 3、4 步后有 9/10 完成。两步都能运行的四组中，筛选有三组同时选对了长期同簇边和测试最大簇的方向。1205 强非 IID 是反例。
- 1204 强非 IID 的 client2 在第 5 步只剩两个非空簇。第 2、3 步都能启动，第 2 步将末段测试最大簇由 88.60% 降至 17.55%。
- 两组已知失败配置的多客户端回退分别把 client1 的末段测试最大簇从 95.80% 降到 20.75%，从 84.05% 降到 16.85%。10 个非空簇只能保证初始化可执行。200 轮留出指标用于判断小簇与测试质量能否保持。
- E38 用相同选定快照、中心初始化、全客户端私有频数校正比较全程 0 和 0.5 间隔保护。四组、200 轮的结果覆盖 STL-10 固定表示、IID 与 Dirichlet α=0.1，并含两组已知高风险配置。无法由这四组推断 50% 门槛的普遍触发率或适用性。公共集强偏移、其他数据集或 (K)、持续更新的编码器仍属于待验证范围。[E38 审阅](../evidence/SNAPSHOT_EXTERNAL_COMPARISON_20261118.md)
- 额外编码、KMeans、快照存储或重放都属于一次性准备开销。E38 的运行内筛选耗时在未触发配置约为 0.10–0.15 秒，在触发配置约为 2.58–3.18 秒。下一轮在同一选定轨迹上比较 B/E/D，计入共同准备成本。
