# 单簇及近单簇退化的短期诊断计划

更新日期为2026-11-06。当前短期目标是定位退化来源，并验证小幅训练调整能否缓解。本文为后续实验设计，执行前需将配置、判定标准和源码冻结到新实验包。

|---|---|---|

|N6、K64、强非IID、seed1002，公共2步|第20/80/160/180/200轮完全单簇客户端为1/2/3/5/6，最终ACC10%、NMI和ARI为0|逐渐加重的长期失效|

同配置下B/E/D的关系、训练轨迹和评估精确一致。定位工作的第一层是三种方法共用的训练过程。全量B作为最小诊断入口，可直接观察学习过程。

既有N6、K10、公共2步长程与重复计时结果继续作为健康参照。两步配置的可用范围需要结合N、K、数据量和划分判断。

## 优先检验的原因假说

公共硬关系越来越偏向同簇后，BCE更新可能进一步推动预测集中。私有伪标签CE提供簇分离约束，二者的相对作用可能随每客户端私有样本、K和初始化变化。

固定总私有5000张时，N2/6/12每客户端私有SGD分别为20/7/4步，公共固定2步，相应步数比为0.10/0.286/0.50。这一计数支持先检验公共更新强度的选择，梯度大小和方向仍待测量。N12改成公共1步时比值为0.25，接近N6原配置。

并行保留其他候选解释，包括小私有数据下冻结表示或伪标签不足、随机头与私有拟合的启动过程、公共分布迁移，以及K增加后目标变化。K64的真类别数仍为10。先用干预区分原因，再决定后续表示或损失调整。

## 第一轮最小实验

固定N12、K10、强非IID、seed1003、M16384、200轮，复用原准备缓存、初始头、私有更新、图和随机流。只跑全量B，新增3条轨迹；已有公共2步原轨迹作为参照。原参照按历史记录使用。

|分支|修改|判别用途|
|---|---|---|
|仅私有更新|关闭公共学生参数更新，继续记录诊断检查点|观察冻结表示、固定伪标签及私有头部训练自身能否维持簇分离|
|公共1步|每客户端公共更新由2步减为1步|检验较小预算能否缓解退化，同时记录边消费量改变|
|公共2步、公共学习率减半|保留原两批边及顺序，将公共有效学习率由0.1调为0.05，私有学习率仍为0.1|在相同公共边预算下检验参数更新强度|

检查点包含0、1、2、5、10及每20轮到200轮。模型时序同时区分当轮私有更新后的教师快照与公共更新后的学生状态。已有历史记录按其实际检查点比较，新的早期检查点完整保存。

记录逐客户端测试ACC/NMI/ARI、占用簇数、最大簇占比和完整簇计数；记录公共无标签探针的占用分布、教师同簇边比例、私有伪标签拟合准确率、私有/公共损失。每客户端每检查点保存严格单簇和≥99%集中的事件及恢复情况。诊断计算、评估及教师监测耗时单列。

第一轮为已知失败种子的探索性定位。报告完整轨迹及变化方向，随后将候选、判定阈值和确认矩阵冻结。现有失败轨迹用于产生假说，确认阶段使用独立运行记录。

## 按结果推进

|第一轮观察|后续优先行动|
|---|---|
|仅私有分支也严重退化|检查初始头、私有伪标签拟合、冻结表示和固定伪标签分布，再确定最小表示/初始化干预|
|仅私有健康，降低公共有效学习率后恢复|优先确认公共更新强度的解释，冻结该候选进行200轮验证|
|公共1步恢复，2步低学习率仍退化|进一步区分边消费与连续两次公共更新的影响|
|两个公共调整都失败|结合私有分支和阶段性探针进一步定位反馈或表示问题，再决定损失等改动|

下一阶段先在同设健康seed上检查副作用，再用运行前选定、未参与选档的新seed确认。既有N12强非IID的seed1001/1002可作健康对照。最终候选需覆盖IID与强非IID，保留200轮、过程集中度和逐客户端尾部风险。

K64/强非IID/seed1002随后单独诊断和确认，保留同K健康种子对照。各K的伪标签与目标不同，分别解释其干预结果。

候选的验收围绕持续和最终集中是否缓解、NMI/ARI及私有拟合是否恢复、健康对照的质量是否保持。确认阶段的数值门槛与比较对象在运行前确定。研究继续接受预定范围内的小幅质量损失，ACC提高无需作为修复条件。

## 修复候选确认后的计算检查

在冻结候选配置下恢复B/E/D，重新检查关系、提交目标、参数和评估的精确一致性，并测量完整头部、准备加加载加头部、生成、通信及内存成本。减少公共预算产生的工作量收益和认证带来的收益分别报告。

N12强非IID现有D/E三seed均较慢，独立列为计算收益边界。该配置三seed均按D→B→E执行；如需专项确认小幅性能差异，应在同配置的重复/种子间平衡方法位置，并固定电源及运行条件。新的顺序设计写入新协议。

## 当前实验排序

1. 编写并冻结N12三分支诊断包，完成小规模代码检查后由用户运行。
2. 审阅诊断结果，选择最小候选，冻结健康种子与新种子确认矩阵。
3. 完成200轮确认及K64异常专项验证。
4. 在确认的可用候选配置上复核B/E/D精确性与资源收益。
5. 再安排固定每客户端400张、私有数量不均等规模实验。新seed静态选路复核继续暂缓。

本计划及2026-11-05的Astra high独立审阅属于设计依据。原因假说、修复效果和更大范围的稳定性仍需按上述实验验证。
