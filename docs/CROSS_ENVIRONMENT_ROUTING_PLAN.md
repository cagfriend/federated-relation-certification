# 三档精确选路的跨环境复测设计

下一轮验证 E42 的固定候选 **512→B、4096→D、16384→B** 在第二个计算环境的适用范围。E42 的 18 格在原环境均通过关系生成判据。[E42 逐格结果](evidence/e42_confirmation/cells.csv)

## 输入和环境

- 复用 E42 原始教师轨迹，覆盖 2021、2022、2023 三个种子，各含 IID 和 Dirichlet α=0.1，三档公共规模共 18 格。在两边核对图、特征、教师头和参考硬关系文件的摘要。
- 优先在另一种 CPU 上使用相同 Python、NumPy 与 BLAS 后端。若改用同一 CPU 上的另一 BLAS 后端，则保留原硬件并记录库版本。两种因素同时变化时，结果按整体环境报告。运行前锁定一个环境，记录 CPU、操作系统、数学库、线程数和计时条件。
- 六端使用同样的已封存快照。每种路径重新初始化缓存，完整重放 200 轮。先在新环境逐轮对比 D/E 和同机全量 B，再对比 E42 的封存关系。首轮初始化和缓存维护均计时，校验和读取文件在计时区间外。

## 计时与判断

18 格 × 三组 B/E/D，共 162 次独立单线程进程。每组连续运行，轮换方法顺序。按各环境自己的配对秒差判读，并报告相对当环境实测最快固定路径的额外秒数、持久缓存大小以及进程峰值。

- 4096 档要求 D 对 B 和 E 分别平均省时至少 3%，且各赢至少两组。
- 512、16384 档检查 E 或 D 是否相对 B 达到同一门槛。一旦出现达标挑战者，记录 B 所付代价。
- 逐格硬关系必须通过核对。若新环境 B 与历史 B 有浮点边界差异，记录位置及涉及的路径。保留同机 B/E/D 的正确性与耗时作为诊断，单列受影响格。

报告按规模、划分和种子列出两种环境的选路结果。若排序改变，定位改在哪些档位并量化原规则的错选开销。第二环境和程序入口待确定。
