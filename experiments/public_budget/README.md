# 固定公共预算下的关系生成计算优化

本轮主问题是：固定学生公共训练工作量后，扩大公共图是否提高关系生成在总流程中的占比，并放大D相对B/E的净省时。质量只作护栏，允许减少学生预算导致小幅下降，不要求协作质量提高。

这是第3.1项的第一阶段——公共库规模与学生更新预算解耦。私有训练数据及步数仍固定；减少私有头部训练工作量留待本轮结果后单独设计。

## 正式配置

Fashion-MNIST；IID和容量约束Dirichlet α0.1；三个既有seed404/505/606。六客户端宽度512×3/2048×3，私有共43616张，约7269/7270张/客户端；各划分私有无标签AE预训练5epoch及一次KMeans后冻结编码器。公共池16384，degree1，K10，头部200轮。私有每轮1epoch、batch128；公共BCE weight1、batch256、学习率0.1。

|case_id|公共样本M|约定图边数|每客户端每轮公共更新|作用|
|---|---:|---:|---:|---|
|m4096_full|4096|2048|8 batch|完整遍历与固定8步共用锚点|
|m16384_full|16384|8192|32 batch|保持原完整遍历方式|
|m16384_fixed8|16384|8192|8 batch|固定学生预算，扩大参考图|

2划分×3seed×3配置＝18组；每组实际训练B/E/D，共54条轨迹。小M完整遍历已经等于8步，因此不再重复跑一个完全相同的fixed8配置。缓存可复用上一轮noniid_clustering已验证的6组准备资产，三规格共享同组私有/公共池/编码器/伪标签及初始头；不复用训练后的头。

## 每轮机制与预算

1. 执行完整私有CE更新。
2. 冻结本轮教师快照。B全量公共前向；E逐样本认证；D关系认证，无法认证时精确回退。
3. **全部方法对整个约定图生成、编码、交换和聚合关系**，学生接收完整计数/N。扩大公共图仍增加生成/协议/内存工作量。
4. 公共学生按原有`[seed,402,client,round,0]`随机流打乱完整图边序。full遍历全部；fixed精确取前8×256边，无放回，执行8步。每轮更换预定随机排列，不重复少数固定边来填预算。
5. 学生始终在当前参数上做新前向。教师缓存仍引用上次教师快照，下轮累计变化包含前轮公共SGD及当轮私有SGD。

同配置B/E/D使用相同公共抽边日程及私有更新，逐轮参数、损失、学生更新步数/端点、接收目标摘要和消息字节必须一致；每轮全图oracle验证关系、候选赢家和每个学生收到的完整目标。固定学生预算没有变成“只认证/通信抽样子图”。

观察器额外记录每客户端累计使用的唯一边、端点覆盖率及最小客户端覆盖率。覆盖处理、摘要、oracle和评估均在方法计时之外，观察器数组不计入方法持久内存；隔离内存回放关闭它。

## 主要比较与质量护栏

**主要指标**是同配置、同seed的D/B与D/E完整头部耗时、含共享准备耗时和绝对省秒。生成耗时及占比、教师真实刷新比例解释收益来源；持久数组、可选进程峰值和消息字节同时报告。先逐seed配对，再取三个seed中位和胜出次数，客户端不充作独立seed。

`budget_effects.csv`另报同M、同方法fixed/full成本和公共步数变化。减少公共更新预算带来的省时不能算成D认证的贡献；认证收益只由同预算下D/B和D/E衡量。

质量护栏：同划分、同seed、同M=16384，以B的固定8步对B的完整32步最终平均ACC作差。下降≤0.01（1个百分点，含1e-12舍入容差）为护栏内；NMI/ARI、最差客户端和同一客户端最小变化另列。超过护栏也完整保存，不中途挑掉配置；护栏是容忍范围而非要求提高。正式检查要求三指标完整；人为不完整报表输入会同时给出pending状态，需看状态列，不解释为正式验收。

不同预算会改变训练轨迹，允许其质量不同；认证自身在相同配置内必须保持B/E/D一致。测试每20轮及最终评估，保留曲线及簇占用，不选最好轮次。不会再以Aggregate优于Local/Self作为本轮前提。

## 计时与资源口径

每轮从私有SGD前至公共SGD后使用整段秒表；包括教师快照、认证/精确回退、完整图消息交换和公共SGD。加方法初始化得到`head_pipeline_seconds`。oracle/coverage/评估/摘要在外，完整调用实际等待时间因此大于单方法列。

`with_shared_preparation_seconds`另加本组最大公共池准备成本和特征载入。C0包含AE、全16384池/私有/测试特征、KMeans和写盘；每方法完整计入，不按3方法摊薄，不因复用现有缓存记为零，也不视为每个M的最小独立冷启动成本。

配对主运行B/E/D共存、顺序按seed和轮次轮换。使用三个既有seed，属于适用场景探索，不是独立新seed/单方法进程性能确认，也不是实际并行FL轮时延。静态选路复核的暂缓安排不变。

持久方法数组范围沿用原核心：头参数、候选缓存及协议数组，排除共同特征/图、Python对象、覆盖观察器和瞬时临时数组。可选memory-audit只对最大M fixed配置，分别隔离B/E/D、两个划分、三个seed，共额外18条完整训练回放。它们关闭oracle/评估/覆盖，最终头摘要及持久数组与配对结果对账，只取CPU进程峰值工作集，**其耗时不用于性能比较**。不测AE准备峰值或GPU显存。

三方法使用相同自适应完整/差分/无变化编码，同配置通信相同，不预设新增通信压缩。固定leader0、全员在线、可靠内存交付，未接恢复协议。

## 运行

在工作区根目录执行正式实验：

```powershell
cd C:\Users\tjp\Documents\Codex\2026-10-14\new-chat
D:\anaconda\python.exe -m experiments.public_budget.run --preset full --prepare-device cuda --download --memory-audit
```

输出`experiments/public_budget/results_full`。主实验54条轨迹；`--memory-audit`额外18条隔离回放，可省略此选项仅跑主实验并报告持久数组。旧缓存不存在时重新准备；CPU准备需显式`--prepare-device cpu`及新输出，不假称复用旧CUDA身份。

中断后在同一条命令末尾添加`--resume`。保存配置、种子、运行库、源码和内存选项冻结；完整case保留，未完成case从第一轮重做。末尾必须出现`Finished`及`completed.json`，才算18组全部完成。

默认查找旧noniid_clustering结果中匹配的4096锚点，逐轮核对B/E/D头、public loss、消息、学生步数/端点、持久数组及评估。历史参考存在时冻结其文件摘要；不匹配的设备/配置不强行复用，记录checked=false。重新部署需要先解压归档JSON，并重新准备缓存；旧绝对路径不适合异机直接resume。

开发路径验证：

```powershell
D:\anaconda\python.exe -W error::ResourceWarning -m unittest experiments.public_budget.test_budget -v
D:\anaconda\python.exe -m experiments.public_budget.run --preset smoke --memory-audit
```

smoke仍使用官方数据：训练1024、测试128、宽度32/64、公共池128/实际32或128、AE1epoch、头3轮、batch16；small full1步、large full4步、large fixed1步。同样18组54轨迹，可选18个内存回放，只验证路径，不提供正式性能或质量结论。

## 输出与证据

- `environment.json`、`completed.json`：冻结设计/来源和全部结果文件哈希。
- 每case JSON：逐轮整段/分段耗时、目标/参数/调度摘要、完整图关系与候选检查、完整评估和覆盖轨迹。
- `summary.json/csv`、`paired_cost.csv`：同配置D/B、D/E成本比、绝对省秒、生成占比及资源代价。
- `budget_effects.csv`：固定学生预算与完整遍历之间的成本变化，单列归因。
- `quality_guardrails.csv`、`final_clients.csv`：允许小幅质量下降的护栏及逐客户端数据。
- 可选`memory_summary.csv`：独立单方法进程峰值；不替代计时证据。

旧public_scaling、noniid_clustering、collaboration_mechanism源码及结果不改动。正式实验由用户运行；开发阶段只做单测、官方缩小smoke和完整配置/缓存的只读预检。
