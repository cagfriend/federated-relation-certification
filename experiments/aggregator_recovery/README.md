# 临时聚合者切换、状态交接与恢复

本轮验证半分布式方案中尚未实现的恢复路径。**首版是实际序列化、可靠内存传输的协议实验，不运行模型训练，不声称已经实现真实网络容错或分布式共识。** 使用同一套原有关系编码，原 `public_scaling` 13 个源码保持不变；未来接回真实训练时，学生只能消费提交后的目标。

## 三个对照

|策略|正常运行|在线交接|突然故障|
|---|---|---|---|
|rebuild|无热备|新聚合者收集所有存活客户端当前完整关系|同样全量重建|
|on_demand（主候选）|无热备|旧聚合者将已提交关系库批量发给新聚合者，再处理本轮变化|旧进程状态丢失，退回全量重建|
|hot_backup（扩展对照）|每轮提交后复制关系变化给候补，收到确认后才进入下一轮|候补使用已确认的上一提交版本接管|候补接管、剔除故障成员贡献，再收本轮变化；新候补重新同步|

正常运行不轮换聚合者，只有指定事件发生时才选举。hot_backup是额外机制，不是原方法默认已有能力。不能只报告故障时少发的数据：首次同步、每轮复制、ACK和换候补后的全量同步都纳入总账。on_demand也不保证比收集当前完整关系更省，实际结果决定是否采用。

所有客户端预先拥有相同公共样本和图。首次图注册计入成本；换聚合者不强加重新广播整张图，因此rebuild是相对较强的对照。CPU串行处理，不人为设置带宽让某个方法获胜。

## 每轮与恢复流程

1. 取得本轮各客户端的固定硬关系输入；三个策略使用同一输入和事件序列。
2. 客户端上传全量/差分/无变化消息。接收数据先进入staged，不立即改变已提交状态。
3. 聚合者为当前active成员求和，下发暂存目标；接收方先放在pending，不允许学生消费。
4. 全部active成员准备完成后，在本实验声明的原子提交屏障内推进版本，正式应用目标。hot_backup再进行复制并确认。
5. 若在部分上传或部分下发期间故障：保留已提交版本，丢弃所有未提交的staged/pending；销毁故障进程状态，把它从成员集剔除。
6. 存活成员按已知ID选最小可用候选，序列化候选通告、投票、任期确认与ACK；任期加一，旧任期数据被拒绝。故障发现和一致存活成员名单由注入器提供，不测选举超时/故障检测。
7. 根据策略恢复关系库，显式广播全量重建或沿用已提交参考的请求，再重试同一轮输入。只提交一次，版本不因失败尝试增加。
8. 故障客户端若干轮后重新加入，进程缓存为空，只提交加入时的当前关系，不补历史轮次。目标分母由active成员数决定。

同一份总计数不足以一般地支持单个成员删除或全量替换，因此聚合者保存每客户端关系。候补也保存这份关系库，额外持久数组内存必须报告。发送端复制编码只使用自己保存的已提交历史和候补确认版本，不免费读取候补内存来构造差分。

重复上传幂等只覆盖同一事务、同一发送者的完全相同数据包；同一发送者的冲突重复被拒绝。不将此扩大为所有控制消息或任意故障的幂等承诺。

数据消息的wire ACK只表示收包，不是持久提交证明。热复制只有在接收端解码校验、可靠内存屏障结束后才记录可接管的确认版本；此屏障不是额外实现了一套网络ready/共识协议。提交前全部准备与最终原子决议也由本模拟器屏障提供；若未来改为真实网络，需要实现并重新计入相应协调与故障处理成本。

## 六类场景与配置

正式配置：6客户端，公共样本4096、10个合成簇、200轮，seed404/505/606。图度按场景为1或8；模型宽度元数据512×3/2048×3仅用于沿用接口，不在这里计算模型前向。

|场景|图度|样本簇变化概率|事件轮次|
|---|---:|---:|---|
|control_sparse|1|0.001|无故障，观察纯复制负担|
|handoff_sparse|1|0.001|第60/130轮，旧聚合者在线交接且继续参与训练|
|crash_upload_sparse|1|0.001|第60轮部分上传后故障|
|crash_down_sparse|8|0.001|第60轮部分目标下发后、提交前故障|
|frequent_crash|8|0.001|第20、40、…、180轮部分上传后故障|
|crash_dense|8|0.2|第60轮部分上传后故障，较大输入变化|

故障成员在3轮后、该轮开始时重新加入。总计6场景×3seed=18组，每组3策略，共54条协议回放。seed用于生成输入、轮换策略运行顺序；这不是54次模型训练，也不据三个seed推断真实故障分布。

输入由可复现的样本簇标签轨迹生成，再计算固定图上的合法“是否同簇”关系，不是独立随机翻转边。`change`是样本标签变化概率，**不等于关系翻转率或模型参数更新幅度**。不使用Fashion-MNIST，不报告ACC、NMI或ARI，不把合成关系当训练输出。

## 重点看哪些结果

1. **零错误要求**：本轮目标逐边等于当前active客户端关系之和；提交只前进一次；无pending目标被应用；成员退出/重入、term、leader、版本和分母与事件oracle一致。所有策略目标完全相同。
2. **累计总字节（首要资源指标）**：包含图setup、所有数据/控制/ACK、废弃失败尝试、在线交接、冷恢复请求、候补复制及重新入组。`event_round_bytes`包含整个事件轮（也含正常数据和提交），不是纯恢复快照大小。
3. **复制账本与故障频率**：`replication_bytes`单列；与无故障、低故障和频繁故障对照一起读，检查热备是否把恢复节省转移成常态开销。可能得到负收益，照实保留。
4. **本地处理时间**：`local_seconds_with_setup`包含序列化、解码和状态维护；`recovery_seconds_with_aborted_attempts`从事件轮失败尝试或交接开始，到成功重试且完成相应复制为止。两者不包含网络传播、检测等待或训练，因此不能写成真实恢复停顿。
5. **持久数组内存**：记录所有节点实际拥有的关系/计数/角色库数组，去除同对象重复引用；这是额外内存的可审计下界，不是Python对象总内存或进程峰值。未计共享输入trace/图。

`summary.csv`逐seed给出全部指标；`summary.json`按同seed与rebuild配对后取中位数，`report.md`展示主要字节比。`completed.json`为完成标志。原始JSON保存逐轮目标摘要、成员与通信分类账；目标可从同seed输入独立重构检查，`check_case`不需要旧训练缓存。

## 明确的实验边界

可靠内存交付、可信客户端、注入器已知故障与存活成员；每次只故障旧聚合者，候补同步屏障可靠。最后提交决议作为原子屏障，**不覆盖提交决议传播中崩溃、网络分区、同时双故障、候补同步失败或拜占庭**。本轮不实现Raft/Paxos，不声称一般分布式共识安全性。

本轮不评估故障后模型/优化器恢复、断连期间本地训练、真实学生消费目标或聚类质量。后续接回训练与真实传输时需要新的集成验证。非IID＋模型异构仍为必做后续项目，没有被本实验替代。
